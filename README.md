# llm_interceptor

M2 adds an explicitly activated reverse proxy for a remote Ollama client in Observe mode. Prepare the configuration, click Start Observe proxy, then set the client's Ollama base URL to the displayed Mac LAN listener. Launch performs no listening or network mutation. Clear session or close the window to stop the relay worker. Automated ARP/PF redirection remains unimplemented. A manually staged LAN transparent lab trial delivered an Ubuntu OpenCode `/v1/chat/completions` response, visible in GUI Requests, with temporary receive-checksum offload disabled; see [the runbook](docs/M6_LIVE_DEMO_RUNBOOK.md) for the historical trial and rollback record.

## Build and test

Requires macOS Command Line Tools, CMake 3.24+, Ninja, and Qt 6.11+ Core, Widgets, Network, HttpServer, and Test. Install these dependencies through your preferred package manager. If Qt is not discovered automatically, put personal CMAKE_PREFIX_PATH settings in ignored CMakeUserPresets.json or pass them at configure time.

```sh
cmake --preset debug
cmake --build --preset debug
ctest --preset debug --output-on-failure
./build/debug/llm_interceptor.app/Contents/MacOS/llm_interceptor
```

The release and sanitizer presets use the same commands with their respective names. Sanitizer configuration checks compiler/linker support for AddressSanitizer and UndefinedBehaviorSanitizer. Tests run offscreen without capture privileges. M0 synthetic fixture checks can also run with `python3 -m unittest discover -s tests -p 'test_m0_fixtures.py' -v`.

On macOS with Python 3 available, `ctest --preset debug -R '^m6_codesign_smoke$'` checks signed GUI staging with the system `codesign` tool and the built identity preview CLI. It uses a temporary copy of the built app and runs offline without installing a helper or requiring administrator privileges.

On macOS with Python 3 available, `ctest --preset debug -R '^m6_helper_package_codesign_smoke$'` stages the built helper with the launchd helper packaging script in a temporary directory. The test uses the system `codesign` tool to verify the staged copy’s embedded signature. It runs offline without installing the helper or requiring administrator privileges.

GitHub Actions runs the debug, release, and sanitizer presets on a macOS runner for every push and pull request. The workflow installs Qt 6.11+ and Ninja, builds the application, and runs the same CTest suites; it performs no live network activation.

## Configuration and permissions

Select an active Mac interface, then enter the remote client's and Ollama server's unicast IPv4 addresses, server TCP port from 1 to 65535, and comma-separated API paths. **Prepare configuration** validates and stores these settings without opening a listener. **Start Observe proxy** binds to a usable IPv4 address on the selected interface and accepts connections only from the configured client IPv4. Set the remote client's Ollama base URL to the LAN URL shown by the app. Requests sent to the unchanged server address are not redirected. The interface list also includes inactive and loopback interfaces, but they cannot be used for the LAN listener. Clear the session to change its configuration.

The proxy listen port defaults to `11434` and can be set to **Automatic**. Use a free port on the Mac. Clear session stops the listener; restore the client's original Ollama base URL afterward. The current GUI supports the explicit remote-client workflow; the lower-level transparent listener remains available to offline tests and future helper work. The earlier manually operated lab setup is recorded in the [minimal lab demo plan](docs/M6_MINIMAL_LAB_DEMO.md) and [runbook](docs/M6_LIVE_DEMO_RUNBOOK.md).

Launch and offline tests need no capture privileges; socket-based tests need permission to bind synthetic loopback endpoints. Future capture/injection/PF operations will use a scoped helper and explicit activation; never run the GUI as root. Capture only authorized traffic. M6 has bounded manual Wi-Fi/PF request evidence; automated activation, privileged-helper lifecycle, and recovery remain incomplete. See [PLAN.md](PLAN.md) and [M0 lab record](docs/M0_LAB.md).

BoundedHistory retains a configured positive maximum row count and limits each summary to 4096 UTF-16 code units. Append/snapshot/clear are mutex-protected. SessionController and GUI are owner-thread objects; immutable configuration copies cross component boundaries. The Observe view retains only matching POST JSON object bodies for configured API paths, with response status and raw body details. Nonmatching bodies are forwarded but never stored. No authentication headers are displayed or retained.

## Observe relay limits and behavior

Qt HTTP Server supplies HTTP/1.1 parsing and Qt Network supplies upstream connections. Requests are buffered up to the configured body limit (default 1 MiB); decoded body bytes are forwarded unchanged. Response bytes stream incrementally with normalized chunked framing. Hop-by-hop headers, including Connection-nominated fields, are removed; redirects are returned to the client, not followed. This is an explicit reverse proxy: the client changes its base URL. CONNECT and protocol upgrades are rejected. The GUI binds to the selected interface IPv4 and filters accepted sockets by the configured client IPv4. The underlying ProxyServer API also supports loopback-local configuration. Neither configuration redirects traffic automatically.

Limits: 24 accepted downstream sockets, 8 active relays, 32 KiB headers, 4 KiB URL, 100 header fields, 64 KiB upstream read buffer, approximately 64 KiB downstream socket queue, 2-second library default transfer timeout (the GUI uses 120 seconds to allow initial model loading) and keep-alive idle timeout. Request retention defaults to 100 rows and 8 MiB of retained body bytes; the configuration page allows 1–1000 rows and 1–256 MiB. Oldest records are evicted to stay within both limits. A request larger than the byte budget is inspected live by the relay but not retained. Oversized requests are rejected by the mature parser. The GUI's explicit proxy accepts only its configured remote client IPv4 on the selected interface. Automated live network redirection remains unimplemented. A November 8 manually staged client neighbor override and PF redirect to the Mac LAN listener returned HTTP 200 for `/api/version` while `net.link.generic.system.hwcksum_rx=0`; a subsequent Ubuntu OpenCode `/v1/chat/completions` request to the unchanged Ollama URL succeeded and appeared in GUI Requests. Direct `/api/version` recovered after neighbor deletion; the neighbor and checksum setting were restored. The user then loaded the original PF configuration and released the trial enable token; output confirmed PF `Status: Disabled` and `No pf starter references held`. One established Mac-to-upstream PF state had been observed earlier, but its disappearance was not separately verified. This does not establish default-checksum operation or automated recovery. ProxyServer lifecycle/history methods must be called on its owning thread; network/parser work runs on a separate Qt thread.

The default observed API paths are `/api/generate`, `/api/chat`, and the OpenAI-compatible `/v1/chat/completions`. The current request list shows method, configured path, response status, and original JSON body details. The request view has separate full JSON and `messages` sections; select a message to inspect its complete JSON value. For responsiveness, the message list displays up to 1000 items from requests up to 1 MiB. Selected JSON up to 64 KiB and 32 nested objects/arrays appears indented in a monospace font; larger, deeper, or invalid JSON uses its raw text. This display formatting leaves forwarded and retained raw bytes unchanged. New history entries preserve the selected request and its detail scroll position while that request remains retained. Details use the displayed record snapshot, so eviction cannot substitute a different request. The Requests page reports retained request counts, modified counts, and body bytes. Export writes a JSON Lines archive and redacts common credential fields by default; import loads a bounded offline replay into the inspection view. Replay records cannot be sent to an upstream server and must be cleared before starting the proxy. Review exported files before sharing: free-text prompts, message content, and custom fields may contain secrets that do not use recognizable credential field names. See [M5 inspection behavior and limits](docs/M5_INSPECTION.md) and [offline baseline](docs/M2_BASELINE.md).

Repeated request Cookie fields are joined with semicolons; supported standard list-valued fields are joined with commas before Qt Network sends them. Repeated fields outside these supported classes, including unknown custom fields and singleton authentication/content-type fields, return HTTP 400 explicitly instead of silently losing a value. Response Set-Cookie fields remain separate.
