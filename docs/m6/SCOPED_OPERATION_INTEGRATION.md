# Scoped network-operation integration: first offline increment

This is the implementation record for the first backlog package C increment. It composes the existing reviewed pieces — pre-mutation gate, host lease, both durable PF journals with their coordinators, typed PF anchor and enable-reference commands, and the ARP packet writer — into one real scoped session execution behind the lifecycle's operations-factory seam. Everything here is offline and injectable: no production entrypoint constructs it, no live PF/ARP command runs from this slice alone, and no GUI change was made. The three-role review and the deferred test phase remain open; this document records what is real, what is injected, and what enablement is still missing.

## What this increment adds

- **`PosixSpawnChildProcess`** (`src/network`, `interceptor_read_only_xpc`, Qt-free): a bounded child-process engine for the system-library-only helper. One fixed absolute program with an explicit argument vector through `posix_spawn` — no shell, no PATH search, no caller-supplied environment; the child starts with only the three standard descriptors (`POSIX_SPAWN_CLOEXEC_DEFAULT`). Bounded by construction: pending stdin capped at 64 KiB, captured output at 256 KiB, every wait at a caller-supplied millisecond deadline, non-blocking pipes with poll, waitpid WNOHANG reaping, kill-and-reap on teardown, and no process leak at destruction. It exists so the installed helper can run typed commands without QProcess; the Qt runners remain the reference implementation of the same loops.
- **Spawn-backed typed command adapters** (`src/network/PosixSpawnTypedCommandProcess.*`): the two existing child-process seams (`PfAnchorChildProcessFactory`, `PfEnableReferenceChildProcessFactory`) acquire spawn-backed implementations. The reviewed runner state machines (`QProcessPfAnchorCommandRunner::execute`, `QProcessPfEnableReferenceCommandRunner::execute`) and every coordinator, journal, and operation layer above them are reused unchanged — this slice adds a child factory, not a second command path. `PfctlPosixSpawnEnableTokenVerifier` runs the read-only `/sbin/pfctl -s References` query through the engine for the enable-reference journal: an exactly matching decimal after a token-naming line is Active, a recognized empty table ("no references" / "references: 0" / "refs: 0") is Absent, and everything else — nonzero exit, unknown output shape, over-limit output — is Unknown, so a cleanup obligation is never cleared on hope. The exact live output shape of `-s References` on the target build is unverified; a shadow observation is listed under enablement below.
- **`ArpRedirectRefresher`** (`src/network`): the session-long bounded ARP redirect loop required by backlog C, grown from the one-shot probe semantics. `start` sends the pairwise redirection frames once and then re-announces only the client mapping for the server IP on a 250–2000 ms interval (default 500). A failed or uncertain initial redirect corrects immediately and fails the start; a failed refresh tick stops the timer, sends the pairwise corrective frames, and reports unhealthy through `redirectHealthy()` so the watchdog path stops the session. `stop` (Stop, watchdog expiry, or any cleanup) stops refreshing and sends the corrective frames; `restoreNeighbors` still sends the full pairwise restoration afterward. Corrections are retry-safe and idempotent. As before, an accepted write only means the BPF writer accepted one frame; it is not proof the client's cache changed.
- **`ScopedSessionSystemOperations` / `scopedSessionOperationsFactory`** (`src/proxy`, `interceptor_proxy`): the real operations object returned through the lifecycle's factory seam. It derives from `PfAnchorRecoverySystemOperations` (the `final` was removed so the composed object can own its collaborators) and owns: both spawn-backed runners and their factories, both durable journals opened from the trusted directory, two PF enable-reference owners (active and startup-recovery; one shared journal, distinct owners), the anchor recovery coordinator with the command cleanup verifier, the ARP refresher, the sysctl-backed settings seam, and the delegate below. The base class remains the single journaled command path.

## Implemented sequencing

Startup, driven by the existing NetworkSession state machine over the composed object:

1. **Fresh pre-mutation gate.** The derived object runs the uncached `HelperPreMutationGate` before the base's journaled path, so no session mutation — including pending-reference reconciliation — can precede a fresh gate pass. Nothing is mutated by the gate itself.
2. **Lease and journal recovery clear.** The base class reconciles the enable-reference recovery journal through the startup coordinator (distinct owner consumed by recovery), then the delegate issues the exclusive session lease token bound to the host flock lease acquired at bootstrap. One session per process; HostSessionLease still enforces single-instance.
3. **PF enable-reference capture.** Exact token acquisition through the journaled enable-reference coordinator over the spawn-backed typed runner; the durable journal owns every uncertain acquire.
4. **Owned-anchor install.** `snapshot.pfRules()` generates the scoped one-client/one-server/one-port rdr and pass rules (upstream exclusion from the inbound match by construction — the inbound rdr matches only the client IP, so the research host's own upstream traffic never loops). The authorization layer enforces effective root, PF enabled, both main-ruleset attachment references, exact lease token, and — for installs — the session anchor not already loaded, so a leftover anchor must be reconciled through the journals before install. Install itself goes through the journaling anchor coordinator.
5. **Active-evaluation verification before ARP.** `beginArp` re-collects PF diagnostics and requires the session anchor loaded with both owned rule types present and both attachment references active before any redirect frame may be sent. ARP then starts the refresh loop.
6. **Capability release and Heartbeat/Stop** flow unchanged from the [session-control contract](HELPER_SESSION_CONTROL_CONTRACT.md).

Teardown stays exactly the NetworkSession reverse order: cease ARP + corrective frames (`endArp`) → pairwise neighbor restoration → anchor removal with verified-empty cleanup (existing `PfCommandAnchorCleanupVerifier`; never a bare empty response alone) → owned-state/settings restoration by compare-and-write (`net.inet.ip.forwarding`, `net.inet.ip.redirect` — sysctl names observed read-only on the target system) → exact-token PF reference release (only after anchor cleanup verified) → lease release. Each uncertain command keeps its journal obligation; a crashed session durably records `cleanup_needed` for the recovery path.

| Piece | Status |
| --- | --- |
| Order, state machine, journals, coordinators, token discipline | Real (existing reviewed code, reused unchanged) |
| Command execution engine | Real, Qt-free, but exercised in this slice only through build (no test or live run yet) |

| Settings read/write | Real sysctl-backed implementation with an injectable `NetworkSettingIo` seam |
| ARP redirect/refresh/corrective frames | Real encoding and sequencing; packet writer and timer are injected (`ArpPacketIo`, `ArpRefreshTimer`) — production would inject `MacBpfArpPacketIo` |
| `pfctl -s References` output shape | Parsed defensively (Active requires an exact token match; anything unrecognized stays Unknown); the exact live shape is not yet observed |

No production entrypoint constructs the factory from this slice: no GUI wiring, no installed-service Start dispatch, no live PF/ARP/BPF operation happens because this code was written.

## Installed Qt-free production port (final backend slice)

The installed system-library-only helper cannot link Homebrew Qt, so the Qt composition above cannot run in the reviewed root process. The canonical implementation split is now explicit: the Qt `ScopedSessionSystemOperations` remains the fixture and research-host implementation of these semantics (tests and the leasing/NetworkSession composition stay on it), and `InstalledScopedOperations` (`interceptor_read_only_xpc`, new) is the production implementation behind `InstalledSessionControlBackend` — same ordering, discoverable reasons, and fail-closed rules, expressed with std types and one private dispatch queue (the refresh timer ticks on the same queue, so Start/Stop/Heartbeat/watchdog can never interleave a mutation).

What the installed backend really does per accepted Start, in order: durable obligation journal check (a non-empty journal triggers the ordered reconciliation first, under the journal-order integrity invariant that the enable-reference record always precedes any anchor or settings record: a journal with no token record, or an unnamed uncertain token, keeps `recovery_pending` with no command run; with a named token the reconciliation runs in teardown order — owned anchor removed with verified-empty listings, journaled previous settings written back, exact journaled enable reference released with `-s References` absence verification; only a fully verified reconciliation truncates the journal and proceeds, while any failed step keeps it and rejects as `recovery_pending`, with the failed step recorded only in the helper-side bounded reject log) → fresh neighbor facts (interface MAC from `getifaddrs` live/running; client and upstream MACs from `arp -n` parses that must resolve on exactly the session interface) → sysctl snapshot → `pfctl -E` exact-token capture (single `Token : <decimal>` line parse, journaled before anything else owns) → scoped anchor install (`pfctl -a llm_interceptor/<key> -f -` with the exact three-rule set from the tuple; journal record) → active-evaluation verification (`-s nat`/`-s rules` listings must each carry the owned rule type; never inferred from an empty response) → kernel settings only where not already desired (previous values journaled) → pairwise ARP redirect frames over `/dev/bpf` (BIOCSETIF, EN10MB, source-header completion confirmed) → bounded 500 ms refresh re-announcing the client mapping only. Teardown is exactly reverse: cease refresh + pairwise restoration frames (real peer MAC as ARP sender — a dry-run-caught bug, fixed) → anchor `-F nat`/`-F rules` plus verified-empty listings → settings restored to journaled previous values → `pfctl -X <token>` with `-s References` absence verification (Active/recognized-empty/Unknown) → journal truncated only when every step verified; any uncertain step keeps the record so Stop retries re-drive it and `cleanup_pending` stays truthful.

Real versus injected for this slice: the spawn engine, journal file discipline, ARP encoding, BPF setup, reference/listing parsers, and dispatch ownership are real code, but the only execution evidence is the throwaway offline dry run (deleted after; fakes for commands/ARP/settings, temp journal directory) which passed every ordering assertion, plus the existing offline suite. No live pfctl/arp/BPF operation ran in this checkout; a scratch program read the `en0` MAC via getifaddrs and read-only `sysctlbyname` name lookups were the only system observations. The Qt fixture path and `scopedSessionOperationsFactory` are unchanged and still own no production entrypoint.

Each seam (`InstalledScopedCommandIo`, `InstalledScopedArpIo`, `InstalledScopedSettingIo`, `InstalledScopedJournal` via the state-directory descriptor) is injectable, so the deferred test phase can drive the full matrix offline. Known shallower-than-Qt verification, deliberately: the installed active-evaluation check requires the two owned rule types in the anchor listings and token attachment via `pfctl -E`'s own enable semantics, but does not separately verify the two main-ruleset attachment references the Qt `PfDiagnostics` path checks; the lab phase must observe whether that difference matters on the target build. Neighbor identity here is one fresh `arp -n` observation per Start, not the repeated exact-neighbor verification machinery of the Qt path.

## Installed-phase timing and the stderr-drain wedge (live-lab finding, fixed)

A wedged live Start (captured `pfctl -E` token, then the helper spun at 100% CPU forever, never completing) exposed a concrete unbounded wait in the installed typed-command runner: the output loop drained only stdout, while the engine's readable wait reports either stream as pending. `pfctl` legitimately writes warnings to stderr on `pfctl -a <anchor> -f -`, so the loop re-entered with stdout empty, read nothing, and spin-looped without ever reaping — exactly the phase after token capture. The loop now drains **both** channels each iteration, each bounded at the existing output cap, and captures stderr bounded (`Result::standardError`) for lab diagnostics; the sibling typed state machines and the spawn-based enable verifier already drained both, so the defect was unique to this runner. Per-command deadline is 2000 ms (was 4000) so six sequential bounded commands cannot structurally exceed the 10 000 ms Start client deadline.

Every installed Start/Stop phase now emits one bounded, non-sensitive `os_log_error` line — `llm_interceptor.scoped-phase <phase> duration_ms=<n>` with fixed phase names (`start_total`, `journal_reconcile`, `neighbor_facts`, `settings_snapshot`, `pfctl_enable_token`, `anchor_install`, `active_evaluation`, `settings`, `arp_open`, `arp_first_frames`, `stop_total`), durations from the monotonic clock clamped to `[0, 600000]` ms. A phase whose line is absent from the log is the phase that did not complete; combined with the helper's bounded reject reason this names the failing boundary without tuple, identity, or path data. These lines are real (os_log now), observed live only in the lab; durations recorded in tests are fake-injected and are not evidence.

Live classifier ground truth (macOS 26/27 build, blocker 7): `pfctl -E` and `pfctl -s References` output is prefixed with exactly two ALTQ lines (`No ALTQ support in kernel`, `ALTQ related functions disabled`), and the empty reference state prints `No pf starter references held` rather than the three previously recognized empty markers. The installed token and reference classifiers now tolerate exactly that bounded preamble (before the Token line / anywhere in the reference scan) and recognize the observed empty-state line as Absent; every other unrecognized shape keeps the uncertain/fail-closed verdict. The `journal_reconcile` phase line now always logs (including the empty-journal no-op), and the enable step logs `pf_reference_preflight` for the spawned command with `pfctl_enable_token` naming the parse/append step, so an absent-preflight vs absent-token line localizes the exact boundary next time.

Blocker 8 ground truth (same build): `pfctl -E` prints the two ALTQ lines, a `pf enabled` status line, then `Token : <decimal>`. The enable parse now tolerates exactly that three-line observed preamble before the Token line, and the verified-empty anchor-listing classifier skips the ATLQ status preamble present on EVERY pfctl invocation on this build (whitespace-only was never reachable live). All other shapes stay fail-closed uncertain; the `-X` release and `-f -` install parse no text (exit-status only), and the nat/rules active-evaluation scans are substring-based so unaffected.
