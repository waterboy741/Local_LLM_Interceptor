# Cross-process transparent listener probe

A transparent `ProxyServer` now generates a 32-byte random secret when it starts. While its listener is active, the GUI owner thread can obtain a copy with `transparentProbeSecret()`. This bootstrap getter currently permits repeated copies; the future handoff must restrict issuance and wipe copies after use. The intended installed helper must receive that secret and the exact interface/client/upstream/listener tuple through an independently authenticated bootstrap channel. That handoff is not implemented. Treat the secret as a short-lived capability and clear every transferred copy after use.

`verifyTransparentProxyProbe()` sends a fresh 32-byte nonce over TCP to the specified selected-interface IPv4 and listener port and requires a bounded HTTP response containing an HMAC-SHA256 over the nonce and tuple. The listener answers only the fixed local probe path for connections sourced from that same interface IPv4; all other self-source requests are rejected, and ordinary redirected client traffic retains the exact client-IP allowlist. The handler checks that its listening socket is still open before answering. The verifier caps its deadline at 3 seconds and response at 1024 bytes. A wrong secret, tuple, port, stopped listener, or malformed response fails closed.

This proves possession of the secret by a live listener at the probed instant, assuming the helper got the secret and tuple from a trusted GUI process. It does not establish code identity, durable listener ownership, upstream reachability, PF attachment, or packet delivery. The helper must use its immutable authorized session tuple and repeat the probe immediately before any PF install; stop or cleanup still requires independent recovery. The existing `TransparentProxyReadiness` token remains process-local and cannot be passed to the helper.

Readiness tokens also retain a private per-bind identity. Stopping and restarting a listener, even on the same IPv4 and fixed port, leaves all prior tokens stale; both the token callback and the public current-readiness check reject them.
