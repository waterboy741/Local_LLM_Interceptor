# Trusted bootstrap handoff protocol

`TrustedBootstrapHandoff` is offline plumbing for a future GUI-to-helper session bootstrap. It carries the complete validated `SessionSnapshot` and the transparent listener's 32-byte probe secret over one connected Unix stream. The helper side sends a fresh 32-byte random challenge; the GUI side returns one bounded, length-prefixed versioned frame with a 32-byte challenge echo, a 32-byte probe secret, and JSON containing every session configuration and network fact field, the session ID, and listener port. The secret never enters JSON. The receiver compares the challenge in constant time, reconstructs the snapshot with `SessionSnapshot::create`, and returns a move-only result. The result wipes its owned secret at destruction or transfers it once through `takeProbeSecret()`. Both sides cap frame bytes at 4096 and transport time after authentication at three seconds. Before serialization, the writer caps API paths at 16 entries, 256 bytes each, and 2048 bytes total. The caller owns and closes its socket.

Both `writeBootstrapHandoff` and `receiveTrustedBootstrapHandoff` require an injected `BootstrapPeerAuthenticator` before sending any protocol bytes. That authenticator must verify the executable and code signature of the *connected socket peer* against a fixed trusted installation identity through a kernel-bound identity. UID/GID alone, a PID read without race protection, or identity fields supplied in the frame are insufficient. No production authenticator, listener, GUI call site, helper call site, or app-signing policy is implemented here. Offline tests use a fake authorizer only; they do not prove real app identity.

The GUI must obtain the snapshot from its current transparent listener and fresh lab observations, authenticate the helper, then send it. The helper must independently recheck route/PF/attachment facts and run the cross-process listener probe with the handed-off tuple and secret immediately before any PF install. A serialized `proxyReady` or `anchorAttached` boolean is historical evidence, not authority to mutate. Uncertain state remains a recovery obligation. Do not run live PF or ARP from this protocol.

The frame is a transient secret-bearing buffer. The implementation wipes its mutable byte buffers, and callers must wipe their retained probe-secret copies after use. Qt JSON value/document allocations contain only nonsecret snapshot fields. The binary frame and received secret buffers are wiped on completion or failure; the caller still owns and must wipe the original secret and any secret taken from the result.

`LeasedHelperHost::createFromBootstrap` is an offline consumer seam for this handoff. It passes the transferred snapshot and probe secret to the injected operations factory, then wipes its local secret copy; the factory is responsible for wiping any retained copy. The host creates a distinct command capability. The caller must bind the supplied `VerifiedPeer` to the GUI peer authenticated on this same socket. Host adoption does not prove that binding, recheck GUI-owned listener readiness, or run `HelperPreMutationGate`; production startup must make those checks mandatory before any mutation.
